# Face-count detection accuracy report (#1222)

> **PRELIMINARY — seed dataset only (N=12 synthetic placeholder frames).**
> These numbers are a pipeline smoke test, not a real accuracy measurement.
> Do not cite this report as evidence of production accuracy until the
> dataset is expanded to 200-300 real labeled frames per `data/README.md`.

## Method

- **Model**: MediaPipe Face Detector task (`blaze_face_short_range.tflite`,
  short-range BlazeFace variant), run via the `mediapipe.tasks` Python API.
- **Threshold**: `min_detection_confidence = 0.5` (script default, configurable via `--min-confidence`).
- **Runtime vs. production**: the browser proctoring detector uses
  `@tensorflow-models/face-detection` (MediaPipeFaceDetector, tfjs runtime),
  which does not expose a confidence score at all in its installed version
  (`1.0.3`, latest). This evaluation uses MediaPipe's native Python Face
  Detector task instead, which does — same model family, different
  wrapper/runtime. See `README.md` for the full explanation. Face *counts*
  from the two runtimes are expected to closely track each other since it's
  the same underlying model, but this hasn't been directly cross-validated
  frame-for-frame (would require running both on the same real frame set).

## Interpretation

This is exactly the expected outcome for a placeholder-only seed set, not a
real signal about detector accuracy:

- **NO_FACE recall is perfect (1.0)** because the detector correctly finds 0
  faces in every blank frame, including the ones deliberately labeled `1` or
  `2+` for schema demonstration. This inflates apparent NO_FACE recall and
  tanks NO_FACE precision (every placeholder frame is a false positive for
  "no face").
- **MULTIPLE_FACES metrics are 0 across the board** because no frame in this
  seed set contains any real face at all, so the detector never predicts
  `2+` on anything — there's nothing here to measure multi-face accuracy
  against yet.
- The `placeholder_no_real_face` row (0/7) is the tell: every frame tagged
  that way is, by construction, expected to fail, since there's no face for
  the detector to find.

**No conclusion about real-world accuracy can be drawn from this run.**
